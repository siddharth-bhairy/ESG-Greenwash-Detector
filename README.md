# ESG Greenwash Detector

An NLP tool that scores how **specific and verifiable** a corporate ESG / sustainability report is, and flags **vague, hedge-laden language** that is often a sign of greenwashing.

It fine-tunes [`climatebert/distilroberta-base-climate-f`](https://huggingface.co/climatebert/distilroberta-base-climate-f) to classify each sentence as `SPECIFIC` or `VAGUE`, combines that signal with several heuristic sub-scores, and produces an **Authenticity Score (0–100)** for each ESG pillar and overall. Results are shown in a Streamlit dashboard.

---

## Features

- **Sentence-level classification** of ESG text as `SPECIFIC` (0) or `VAGUE` (1), with a `P(VAGUE)` probability for each sentence
- **Pillar scoring** for Environmental (E), Social (S) and Governance (G), combined into one final score
- **PDF upload**: extract text from a sustainability report and analyse it end to end
- **Interactive charts** (Plotly): score gauge, P(VAGUE) distribution, pillar breakdown
- **Filterable sentence table**: filter by pillar and label, adjust the flag threshold
- **Export** results as CSV (sentence level) or JSON (full report)
- **Training pipeline** with class-weighted loss, early stopping, MLflow tracking and evaluation metrics

---

## How scoring works

Each sentence is scored on five sub-components, which are averaged within each pillar:

| Sub-component          | Weight | What it measures                                 |
| ---------------------- | -----: | ------------------------------------------------ |
| Vagueness (specificity)|    25% | `1 − P(VAGUE)` from the fine-tuned model         |
| Quantitative density   |    20% | Share of sentences containing numeric data       |
| Citation / evidence    |    20% | References to audits, standards, sources         |
| Claim verification     |    20% | Proxy for how verifiable a claim is              |
| Topic coverage         |    15% | Keyword density for the pillar                   |

Pillar scores are then combined:

```
Final Score = 0.40 × E-Score + 0.35 × S-Score + 0.25 × G-Score
```

### Score bands

| Score    | Interpretation                                                 |
| -------- | -------------------------------------------------------------- |
| 80 – 100 | Highly Specific: strong quantitative evidence, verifiable claims |
| 60 – 79  | Mostly Specific: some vague language, generally well supported |
| 40 – 59  | Mixed Signals: notable greenwashing indicators                 |
| 20 – 39  | Mostly Vague: heavy hedge language, few concrete facts         |
| 0 – 19   | Highly Vague: pervasive greenwashing language                  |

All weights, hedge-word patterns and pillar keyword lists live in `config.py`.

## Installation

### Prerequisites

- Python 3.10 or 3.11
- [Git LFS](https://git-lfs.com/) (the model weights are stored with LFS)
- A GPU is optional. The app runs on CPU, but training is slow without one.

### Setup

```bash
# 1. Clone (with Git LFS so the model weights download properly)
git lfs install
git clone https://github.com/siddharth-bhairy/ESG-Greenwash-Detector.git
cd ESG-Greenwash-Detector/esg-scorer-main/esg-scorer-main

# 2. Create a virtual environment
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate

# 3. Install dependencies
pip install -r requirements.txt
python -m spacy download en_core_web_sm
```

> **Run-only install:** if you only want the dashboard and not training, this is enough:
> ```bash
> pip install streamlit torch transformers pypdf pandas plotly numpy
> ```

> **Model weights:** if you cloned without Git LFS, `models/climatebert-esg-scorer/model.safetensors` will be a ~134-byte pointer file and the app will fail to load the model. Run `git lfs pull` to fetch the real file (~329 MB), or retrain with `python train.py`.

## Usage

### 1. Streamlit dashboard

```bash
streamlit run app.py
```

Open <http://localhost:8501>, then:

1. Upload a sustainability report as a **PDF** (text-based; scanned/image-only PDFs are not supported).
2. Optionally enter the company name.
3. Adjust the sidebar settings:
   - **P(VAGUE) Flag Threshold** (0.50–0.95, default 0.65): sentences above this are flagged as vague
   - **Max Sentences to Analyse** (100–3000, default 1000): lower for a faster preview
   - **Show well-evidenced sentences**: also list the specific sentences
4. Review the overall score, pillar cards, charts and flagged sentences.
5. Download the results as CSV or JSON.

### 2. Command-line scoring

```bash
python inference.py
```

This starts an interactive menu where you can score a PDF or TXT file by path, or paste text directly.

### 3. Use it from Python

```python
from inference import load_model_and_tokenizer, score_text, interpret_score

model, tokenizer = load_model_and_tokenizer()
report = score_text("We aim to reduce emissions over time.", model, tokenizer)
print(report)
```

> The exact signature of `score_text` and the fields of the returned `AuthenticityReport` are defined in `inference.py`. Check it before wiring this into other code.

## Training

```bash
python train.py

# Resume from a checkpoint
python train.py --resume models/climatebert-esg-scorer/checkpoint-<N>
```

What `train.py` does:

1. Loads `gold_labels.csv` and `auto_labels.csv`, merges them (gold labels override auto labels for the same sentence), deduplicates, and writes `data/merged_dataset.csv`
2. Stratified train / validation split (default 15% validation)
3. Fine-tunes ClimateBERT with a binary classification head using a class-weighted trainer to handle label imbalance
4. Evaluates with macro-F1, precision, recall, AUC-ROC and Cohen's kappa, with early stopping
5. Logs the run to MLflow and saves the best checkpoint to `models/climatebert-esg-scorer/`

To view experiment runs:

```bash
mlflow ui --backend-store-uri sqlite:///mlflow.db
```

### Key hyperparameters (`config.py`)

| Setting             | Default | Notes                                                    |
| ------------------- | ------- | -------------------------------------------------------- |
| `BATCH_SIZE`        | 8       | Use 4 with `GRAD_ACCUM_STEPS=4` on CPU / low memory      |
| `GRAD_ACCUM_STEPS`  | 2       | Effective batch = `BATCH_SIZE × GRAD_ACCUM_STEPS`        |
| `NUM_EPOCHS`        | 5       |                                                          |
| `LEARNING_RATE`     | 2e-5    |                                                          |
| `MAX_SEQ_LENGTH`    | 256     | Tokens per sentence                                      |
| `VAL_SPLIT_RATIO`   | 0.15    |                                                          |

### Data format

Both CSVs need a text column named `text_chunk` and a binary `label` column (`0` = SPECIFIC, `1` = VAGUE). An optional `pillar` column (`E` / `S` / `G`) is inferred from keywords if absent. Column names are configurable in `config.py`.

## Model performance

The checkpoint included in this repository was evaluated on the held-out validation split after the first training epoch:

| Metric            | Value |
| ----------------- | ----: |
| Macro F1          | 0.874 |
| Precision         | 0.877 |
| Recall            | 0.889 |
| AUC-ROC           | 0.961 |
| Cohen's kappa     | 0.750 |

Target thresholds are defined in `config.EVAL_TARGETS`. Note that labels are largely automatically generated, so these numbers measure agreement with that labelling, not ground-truth greenwashing.

## Limitations

- The model detects **vague and unverifiable language**, not whether a company's claims are actually true. A high score does not prove a company is not greenwashing, and a low score does not prove it is.
- Scanned or image-only PDFs cannot be processed (no OCR).
- Sentence-level labels are mostly auto-generated; only 300 are manually verified.
- Pillar assignment and topic coverage rely on keyword matching, which can misclassify sentences.
- Results depend on PDF text extraction quality (tables and multi-column layouts can produce noisy text).
